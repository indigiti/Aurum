# Aurum V4 trading tools

This release extends the layered modular monolith. Mobile ticket opens above the dock. Exposure ticker distinguishes server-observed P&L from a fresh browser-quote estimate. Position sizing uses server-observed equity, margin, exposure caps and drawdown headroom; it is advisory, not a guaranteed loss ceiling. Break-even moves selected eligible positions to entry without loosening tighter stops; named baskets persist account-scoped position groups; same-side basket SL/TP is transactional with snapshot checks. Drag the selected chart protection handle to preview and explicitly Apply; server validates fresh quotes and book version. Spread and gaps can produce losses at entry stops.

Market depth is the OKX XAU-USDT-SWAP book (contracts). Indicator overlays: BB20/2 and UTC-session VWAP based on available reported base volume, plus existing SMA/EMA. VWAP is a rolling loaded-history approximation of the UTC session, not full tick VWAP; ticker-only candles do not fabricate volume. RSI14, ATR14, MACD12/26/9 shown in compact oscillator panel. Secondary timeframe uses same browser stream independently; time axes are not synchronized. Drawings: two-point trendline, rectangle, Fibonacci levels and 2R risk/reward study; anchored to candle times, saved per timeframe on this browser. Layout and indicator preferences persist locally, not across devices. Price alerts are one-time executable quote thresholds stored in account state; header indicator and in-app notification list; no email or push. Registered accounts require worker activation for unattended observation. Demo is session-only. Strategy simulation adds optional stop/target distances to SMA/EMA crossover rules; next-open fills, adverse gap handling and stop-first if both levels hit. Not a live algorithmic execution system.

PWA manifest and network-only service worker with static offline notice; no account data or trading requests cached or replayed. Installability depends on browser and HTTPS; no offline execution.

## Cloudways worker
Use Cloudways cron once per minute with PHP CLI and the absolute path to private_html/aurum/backend/risk-worker.php --cron-window. It runs repeated observations for a bounded ~50-second window, single-instance file lock. Alternatively supervise --loop continuously. Existing --loop polls REST with one-second delay, not tick-complete; do not run both. Cron scheduling, process supervision, real OKX reachability and worker health must be verified on the actual host. Check /aurum/api/health.php riskWorker (recent-observation vs not-running-or-stale) and Admin System Health. JSON staging and MariaDB production retained; no Node.js server or new schema needed. Do not expose the private worker over HTTP.
