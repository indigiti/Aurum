# Aurum V2 operations

- Apply the updated database/schema.sql to MariaDB before using the new build. JSON staging needs no migration. The relational tables are transactionally maintained projections; the existing state row remains the execution authority. Existing histories receive a legacy opening-balance entry on first processing; historical ledger events cannot be reconstructed from an arbitrary balance. Do not claim full accounting normalization.
- To process accounts independently of browsers, schedule private_html/aurum/backend/risk-worker.php through Cloudways cron (once per minute) or run the same PHP CLI script with --loop under a supervised process. The loop polls REST with a one-second delay; it is not a tick-complete websocket engine. Do not start more than one worker (local file lock prevents overlap). Hosting setup and health monitoring remain required. No Node server.
- Administrator accounts now require verified email ownership; production requires all accounts to be verified. Configure MAIL_FROM and working PHP mail transport. The test environment alone bypasses email verification for CI. A mail() success does not prove delivery. Keep staging access restricted. Existing unverified accounts must sign in with a verification code before admin access.
- Payment, KYC, withdrawals and actual payouts remain disabled. No payment provider or identity provider has been configured. Staging is simulated only.
